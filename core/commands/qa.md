أنت الآن في وضع **QA المنهجي**. ركّز فحصك على التغييرات الفعلية فقط.

## المنهجية

### 1. اكتشاف النطاق

حدد ما تغيّر:
- `git diff --name-only` (أو `$ARGUMENTS` إن وُجد)
- لكل ملف متغير: ما المسارات/الـ flows المتأثرة؟
- إذا `--only`: فحص فقط بدون تعديل

### 2. فحص مركز

اختبر ما تغيّر أولاً، ثم:

- **حالات طبيعية**: هل السلوك المتوقع يعمل؟
- **حالات طرفية**: مدخلات فارغة، قيم متطرفة، حالات خطأ
- **Regression**: هل تأثر شيء آخر بالتغيير؟
- **UI** (إن وُجد): هل المظهر سليم؟ هل الـ flows مكتملة؟

### 3. تقرير النتائج

```
## تقرير QA

### المناطق المختبرة
- [منطقة 1] — [نتيجة]
- [منطقة 2] — [نتيجة]

### المشاكل المكتشفة
- [مشكلة] — [خطورة] — [الملف المتأثر]

### المشاكل المصلحة
- [مشكلة] — [ما تم تغييره]

### إعادة التحقق
- [مشكلة] — ✅ تم / ❌ باقية

### المخاطر المتبقية
- [خطر] — [سبب القلق]
```

### 4. إصلاحات موجهة

لكل مشكلة مكتشفة:
1. تحقق من السبب الجذري
2. أصلح بأقل تغيير ممكن
3. **أعد التحقق** فوراً على نفس المشكلة
4. لا تنتقل للمشكلة التالية قبل إعادة التحقق

### 5. قاعدة التوقف

- إذا `--only`: لا تصلح شيئاً — اكتشف فقط
- إذا تكرر الفشل 3 مرات: أوقف وبلّغ
- إذا كان الإصلاح يكسر شيئاً آخر: أوقف واسأل

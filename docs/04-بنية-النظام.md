# ٤ — بنية النظام: كيف تتركب الطبقات

> هذا المستودع يثبّت نظام تشغيل كاملاً فوق Claude Code. البنية في ٧ طبقات.

## الطبقات

### ١. `~/.claude/rules/` — الحوكمة

ملفان يُقرآن في كل جلسة:

| الملف                        | الوظيفة                                                                                    |
| ---------------------------- | ------------------------------------------------------------------------------------------ |
| `operating-system-policy.md` | السياسة الكاملة — ١٦ قسماً: ترتيب التنفيذ، توجيه النموذج، أمان الذاكرة، بوابات الجودة، إلخ |
| `golden-set.md`              | المرجع اليومي المختصر — الأدوات الافتراضية وجداول القرار                                   |

### ٢. `~/.claude/hooks/` — الحماية (تُنفَّذ قبل/بعد الأدوات)

| الـ hook             | التوقيت             | الوظيفة                                            |
| -------------------- | ------------------- | -------------------------------------------------- |
| `block_dangerous.sh` | قبل Bash            | يمنع ٢٨+ أمراً خطيراً قبل التنفيذ                  |
| `block_secrets.sh`   | قبل Bash            | يكشف أنماط مفاتيح وأسرار في الأوامر ويمنعها        |
| `verify_paths.sh`    | قبل Read/Edit/Write | يرفض مساراً مختلقاً قبل اللمس — طبقة مكافحة هلوسة  |
| `loop_prevention.sh` | بعد Bash            | يعدّ الأخطاء المتتالية ويمنع الحلقات اللانهائية    |
| `auto_format.sh`     | بعد Edit/Write      | ينسّق حسب الامتداد (prettier، php، dart) عند توفره |

### ٣. `~/.claude/CLAUDE.md` — القواعد اليومية

القواعد القابلة للقراءة التي توجه الوكيل كل جلسة: ترتيب التنفيذ، ممنوعات الأسلوب، التحكم في التفصيل، انضباط التوكيل، مكافحة الهلوسة.

### ٤. `~/.claude/commands/` — أوامر سلاش

٢٢ أمراً عربياً: الذاكرة (`/mem-load`، `/mem-save`، `/mem-query`)، التحليل (`/review-ar`، `/refactor-deep`، `/explain-ar`)، جودة DeepSeek (`/eval-last`، `/compare-models`)، وغيرها.

### ٥. `~/.claude/workflows/` — خطوط الجودة

١٠ workflows أصلية: `quick-check`، `deep-review`، `code-quality-pipeline`، `auto-verify`، `multi-angle-analysis`، `sprint`، `canary`، `land-and-deploy`، `freeze`، `design-shotgun`.

### ٦. `~/.claude/skills/` — المهارات الأصلية

٧ مهارات عربية أساسية من تأليف المستخدم: `design-pipeline` (البوابة الموحدة للتصميم)، `checklist-ui` (فحص الجودة البصري)، `arabic-design`، `auto-build`، `debugging-wizard`، `feature-forge`، `spec-miner`.
عشْر مهارات أصلية إضافية: `graphify` (الرسم البياني المعرفي)، و٩ مهارات وكالة متخصصة — `security-ai-generated-code-auditor`، `legal-document-review`، `legal-client-intake`، `engineering-minimal-change-engineer`، `marketing-aeo-foundations`، `marketing-agentic-search-optimizer`، `engineering-i18n-engineer`، `design-brand-guardian`، `engineering-multi-agent-systems-architect`.
(ملاحظة: أوصاف هذه التسع إنجليزية رغم أنها من تأليف المستخدم — تُصنَّف بالـ frontmatter `name`/`description` فقط بلا `license`/`source`، بخلاف مهارات السوق.)

### ٧. الذاكرة — طبقتان

الذاكرة مفصولة عمداً حتى لا تتلوّث مشاريعك ببعضها، مع بقاء الدروس العامة عابرة:

| الطبقة | المسار | ماذا تُحفظ | متى تُحمّل |
|---|---|---|---|
| **عامة** | `~/.claude/memory/` | تفضيلات، أنماط فشل، هلوسات، قيود بيئة | كل جلسة |
| **مشروع** | `~/.claude/projects/<معرّف-المسار>/memory/` | جلسات، قرارات، حقائق ذلك الكود | في مسار المشروع فقط |

- **المعرّف** يُشتق من **مسار العمل الحالي** (نمط Claude Code) لا من مجلد المنزل — فلكل مشروع ذاكرته.
- **مخزن الاستعلامات**: SQLite في `~/.claude/data/deepseek.db` (٦ جداول + ٦ views). الطبقة العامة تُخزَّن بـ`project = NULL`، وطبقة المشروع بمعرّفه.
- **المزامنة**: `sync-memory.js` — يزامن الطبقتين، ويحذف السجلات الميتة لكل طبقة على حدة دون المساس بالأخرى.

**القاعدة عند الحفظ:** هل تفيد هذه المعرفة في مشروع آخر؟ نعم → عامة، لا → مشروع.

## الملحقات (تأتي من مصادرها)

عبر `enabledPlugins` و`extraKnownMarketplaces`، يجلب Claude Code ١٨ ملحقاً من ١٤ سوقاً عاماً عند التركيب — من بينها وكلاء VoltAgent، ومهارات Anthropic، ومجموعة superpowers، وأدوات Vercel/Supabase/Flutter. لا شيء منها داخل هذا المستودع؛ التفاصيل في [٠٥](05-الملحقات-والمصادر.md).

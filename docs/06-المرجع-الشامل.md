# المرجع الشامل — نِظام DeepSeek × Claude Code

> هذا هو الملف الذي يشرح كل شيء: ما الذي ركّبته، كيف يعمل، وماذا يفعل كل أمر.
> اقرأه من البداية للنهاية مرة واحدة، ثم رجع إليه متى شئت. كل معلومة هنا مأخوذة من ملفات المستودع نفسها — لا من الذاكرة ولا من الافتراض.

---

## ١ — ما هذا النظام؟

نظام تشغيل كامل فوق **Claude Code** يعمل بنماذج **DeepSeek** عبر بوابة متوافقة مع Anthropic.
بدل أن تبدأ من الصفر، تركّب هذا المستودع فتحُصل على:

- سياسات حوكمة مكتوبة بالعربية (١٦ قسماً + Golden Set)
- خطافات حماية تمنع الأوامر المدمّرة وتكشف الأسرار
- ٢٢ أمراً عربياً جاهزاً (اختبار، مراجعة، إعادة هيكلة، ذاكرة...)
- ١٠ خطوط جودة (workflows)
- ٢٠ مهارة متخصصة
- نظام ذاكرة كامل (Markdown + SQLite + مزامنة)

**الفكرة:** كأنك ركّبت «روبوتاً مُدرَّباً» يحتوي قواعد الشخصّ، وسلوكات الحماية، والأوامر التي تريد — بدل إعادة بناءها بنفسك.

## ٢ — البوابة والنماذج (الأساس)

كل شيء يعتمد على هذه النقطة. Claude Code يتكلم مع Anthropic، ونوجّهه إلى بوابة DeepSeek:

| الإعداد | القيمة |
| ------- | ------ |
| `ANTHROPIC_BASE_URL` | `https://api.deepseek.com/anthropic` |
| التوكن | `ANTHROPIC_AUTH_TOKEN` — مفتاحك الخاص (متغير بيئة، **ليس** داخل أي ملف) |

### الفتحات الثلاث

| فتحة `/model` | النموذج الفعلي |
| ------------- | -------------- |
| `opus`        | `deepseek-v4-pro[1m]` |
| `sonnet`      | `deepseek-v4-flash-vision-exp` (الافتراضي) |
| `haiku`       | `deepseek-v4-flash[1m]` |

### المزلق الكبير رقم ١: أسماء النماذج

استخدم **فقط** أسماء `deepseek-*`. أي اسم `claude-*` (مثل `claude-opus-5`) يجعل Claude Code يعامله كنموذج Anthropic أصيل، فيرسل ميزات ورؤوس beta خاصة ترفضها بوابة DeepSeek فيتعطّل الطلب.

### المزلق رقم ٢: لا تضع `ANTHROPIC_MODEL`

وجود `ANTHROPIC_MODEL` يثبّت نموذجاً واحداً ويلغي التبديل عبر `/model`. حذفه هو ما يمنحك حرية التبديل.

### المزلق رقم ٣: النسخة

أبقِ Claude Code ≥ **2.1.233**. على نسخ أقدم (مثل 2.1.166) تظهر ثلاثة عيوب توثّقها المجتمع:
- تعارض `thinking:disabled` + `reasoning_effort` → يكسر الوكلاء الفرعيين بـ 400
- تجمّد مصنّف أمان Bash → يتجاوز مهلة ٣٠ ثانية
- رفض `tool_choice` → يعطّل WebSearch/WebFetch

> **تفصّل كل هذا في:** [٠١ — تركيب DeepSeek](01-تركيب-deepseek.md) و [٠٣ — الأخطاء الشائعة](03-الأخطاء-الشائعة.md).

## ٥ — خطوط الجودة (١٠ workflows)

الـ workflow يُشغَّل في الخلفية وينسّق عدة وكلاء/مراحل تلقائياً. الأسماء من ملفاتها الفعلية:

| الـ workflow | ماذا يفعل |
| ------------ | --------- |
| `quick-check` | فحص سريع: مراجعة كود + أمان — بمستويي جهد (low/high) |
| `deep-review` | مراجعة عميقة متعددة المراحل: فحص → تفكير ← code-reviewer ← اقتراحات قابلة للتنفيذ |
| `code-quality-pipeline` | خط جودة متسلسل: تعقيد ← تكرار ← تغطية ← أسلوب ← تقييم نهائي |
| `auto-verify` | اختبار تلقائي + تصحيح ذاتي: يكتشف ← يختبر ← يصور ← يصلح نفسه |
| `multi-angle-analysis` | تحليل متوازٍ من ٣ زوايا: تقنية، أمنية، تجربة مستخدم/أداء — ثم تركيب النتائج |
| `design-shotgun` | يولّد ٣ اتجاهات تصميم متوازية، يقارنها بمعايير، ويدمج الأقوى مع أفضل عناصر البقية |
| `sprint` | خط أنابيب كامل: مواصفات → تخطيط → بناء → مراجعة → تدقيق → شحن. يضبط نفسه حسب حجم المهمة |
| `canary` | مراقبة ما بعد النشر — تتبع أخطاء Vercel والتنبيه عند وجود مشاكل |
| `freeze` | قفل مجلد من التعديل — حماية للمخرجات النهائية، يولّد سكريبت قفل/فك |
| `land-and-deploy` | دمج PR ← انتظار CI ← نشر Vercel ← تحقق المسارات الحرجة |

## ٧ — نظام الذاكرة (كيف يعمل)

الذاكرة طبقتان، مُدعّمة بـ SQLite:

### الطبقتان

1. **الطبقة العامة:** `~/.claude/memory/MEMORY.md` — التفضيلات، أنماط الفشل، الهلوسات، الإجراءات العابرة. تُحمَّل في كل جلسة.
2. **طبقة المشروع:** `~/.claude/projects/<path-id>/memory/` — جلسات وحقائق المشاريع.

### القاعدة عند الحفظ

> تفيد مشروعاً آخر؟ → **عامة**. لا؟ → **مشروع**.

### المخزن

- **مصدر الحقيقة:** Markdown (المجلدات أعلاه)
- **مخزن الاستعلام:** SQLite في `~/.claude/data/deepseek.db`
- **المزامنة:** `node ~/.claude/scripts/sync-memory.js` — ثنائية الاتجاه (Markdown ↔ SQLite)

### أوامر الذاكرة

| الأمر | الوظيفة |
| ----- | ------- |
| `/mem-load` | تحميل الذاكرة + عرض الفهرس والإحصائيات |
| `/mem-save` | حفظ الجلسة (ملخص + هلوسات + قرارات) |
| `/mem-query` | استعلام (بحث/إحصائيات/SQL) |
| `/memory-search` | بحث ذكي بالصلة |

## ٨ — الخطافات (٥ خطافات حماية)

الخطافات تُشغَّل تلقائياً قبل أو بعد كل تنفيذ أداة — تُقفِل الكتابة على بعض الأوامر وتكشف الأخطار:

| الخطاف | متى يعمل | ماذا يفعل |
| ------ | -------- | --------- |
| `block_dangerous.sh` | قبل `Bash`/`PowerShell` | يمنع الأوامر المدمّرة (rm -rf /، git push --force، curl \| bash...) |
| `block_secrets.sh` | قبل `Bash`/`PowerShell` | يكشف الأسرار في الأوامر |
| `verify_paths.sh` | قبل `Edit`/`Write`/`Read` | يتحقق من أن المسارات حقيقية — مكافحة هلوسة المسارات |
| `loop_prevention.sh` | بعد `Bash`/`PowerShell` | يمنع الحلقات اللانهائية |
| `auto_format.sh` | بعد `Edit`/`Write` | ينسّق الكود تلقائياً |

> **جوهري:** هذه الخطافات محمية بثلاثين قاعدتي `deny` في الإعدادات — الوكيل **لن يستطيع حتى تعديلها** بنفسه. هذا مقصود: لا يملك النظام سلطة تعطيل حمايته. عدّلها يدوياً أو أزل القاعدة مؤقتاً.

## ٩ — قواعد المنع (الـ deny)

الـ `settings.template.json` يعرّف ثلاثين نمطاً لـ `deny` (يُمنع دوماً حتى لو طلب الوكيل). تشمل:
- أوامر مدمّرة: `rm -rf /`, `git push --force`, `git reset --hard`, `DROP TABLE *`, `Format-Volume *`
- حماية ملفات النظام: `settings.json`, `hooks/**`, `settings.local.json`
- حماية المفاتيح: `~/.ssh`, `.aws/credentials`, `.credentials.json`, `.auth.sec`

> **الأثر:** الوكيل لا يعدّل الخطافات ولا `settings.json` حتى لو طلبت منه — هو السلوك المقصود.

## ١١ — التركيب (٣ خطوات)

```bash
# ١. استنسخ
git clone https://github.com/slomai1/nizam-deepseek.git
cd nizam-deepseek

# ٢. شغّل التركيب
./install/install.sh              # macOS/Linux/Git Bash
# أو على Windows: .\install\install.ps1

# ٣. عيّن مفتاح DeepSeek
export ANTHROPIC_AUTH_TOKEN="sk-..."
```

ثم شغّل `claude`. عند أول تشغيل تُجلب الملحقات تلقائياً (١٨ ملحقاً من ١٤ سوقاً).

> **خيارات التركيب:**
> - بلا علم: لا يستبدل ملفاتك الموجودة — يضيف الناقص فقط
> - `--force`: يستبدل الموجود بنسخة المستودع
> - `--minimal`: النواة فقط (خطافات + قواعد + أوامر + ذاكرة) — بلا ملحق أو سوق
> - `--dry-run`: يعرض ما سيحدث دون تنفيذ
>
> على PowerShell: `-Force` · `-Minimal` · `-DryRun`

> **جرّب فوراً:** `/model opus` ثم `/model sonnet` — إن عملا، البوابة سليمة و`ANTHROPIC_MODEL` غير مثبّت.

## ١٣ — الترتيب المقترح للاستخدام

1. اقرأ **٠١ — تركيب** ثم **٠٢ — توجيه النماذج** (الأساس).
2. عند حاجتك لأمر: تصفّح **القسم ٤** من هذا الملف.
3. عند حاجتك لفحص جودة: `quick-check` أو `/auto-verify`.
4. عند شك ببطء أو خطأ: راجع **٠٣ — الأخطاء الشائعة**.
5. عند أي عمل واجهة: استدعِ `design-pipeline` أولاً.

> **نقطة انطلاق جيدة:** هوامش هذا الملف تعكس ملفات المستودع الفعلية. إذا صادفت تناقضاً بين ملف والمستودع — **انظر إلى الكود/الملف الحالي، فهو المرجع الأعلى**.
